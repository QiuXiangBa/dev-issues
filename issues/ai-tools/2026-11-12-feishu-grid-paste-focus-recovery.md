## 现象

通过 Codex 的 CUA 浏览器工具操作飞书多维表格网页版，批量补充已有记录和新增行时，实际出现过以下情况：

1. 仅将制表符分列、换行分行的文本放入剪贴板，触发了“AI 粘贴录入”，没有按预期直接填入网格。
2. 一次多行、多列粘贴后，整批内容落在一个单元格内，没有分列。
3. 试图修正该单元格时，`super+a` 实际选中了整批网格记录；随后粘贴较小的数据矩阵，内容在已选记录范围内重复填充，覆盖了已有行。
4. 直接调用 HTML 粘贴时，若页面焦点停在正文容器，本次观察到没有写入效果。工具调用成功返回不能代替结果校验。

这些现象没有统一的错误码，部分操作在界面上看似完成，必须复制回读才能发现错位或重复。

## 原因

本次确认的直接问题是：粘贴前没有可靠地区分“单元格内部文本编辑”“网格单元格选中”“整列或多行选中”三种状态。快捷键的作用对象随焦点与选区变化，较小矩阵粘贴到较大选区时，本次发生了重复填充。

剪贴板格式也会影响处理路径：本次纯文本触发 AI 录入；在明确的网格或列选区上，同时提供 `text/plain` 与 `text/html` 的表格内容后，成功按行列写入。

格式与焦点是本次验证有效的控制条件；没有检查飞书内部实现，不能断言所有纯文本粘贴都会失败，也不能将合并进单元格的现象完全归因于某个 MIME 类型。

## 解决方案

1. **保留完整基线。** 修改前通过界面复制相关表的数据，同时记录当前视图的字段顺序、稳定主键、关联字段、记录数和筛选条件。使用能正确解析带引号及换行字段的 TSV 读取方式；不要只用字符串按换行拆分来判断记录数。
2. **先构造预期结果。** 以稳定主键合并变更，未修改的字段保留原值。关联字段使用能唯一解析的标识，并将关联结果纳入回读检查。若视图有排序，编辑日期等排序字段后，行序可能改变；重新读取当前顺序，再生成后续批次。
3. **确认目标选区。** 对可编辑单元格不要直接用 `super+a` 假定它只选中文字。通过界面退出编辑，明确选择目标网格或目标列；查看最新界面，确认只有预期范围被选中。本次通过只读主键单元格聚焦后全选复制，能可靠读出整表；这不意味着同一方法适用于所有表或写入场景。
4. **同时提供纯文本和 HTML 表格。** 两种格式必须表达同一数据矩阵，HTML 单元格内容先转义，再粘贴到已经确认的网格选区。以下为通用示例，`tab` 表示已有的 CUA 浏览器标签页对象：

   ```javascript
   const rows = [
     ["sample-a", "value-a"],
     ["sample-b", "value-b"],
   ];
   const escapeHtml = (value) => String(value)
     .replaceAll("&", "&amp;")
     .replaceAll("<", "&lt;")
     .replaceAll(">", "&gt;")
     .replaceAll('"', "&quot;");
   const tsv = rows.map(row => row.join("\t")).join("\n");
   const html = "<table>" + rows.map(row =>
     "<tr>" + row.map(value => "<td>" + escapeHtml(value) + "</td>")
       .join("") + "</tr>"
   ).join("") + "</table>";

   await tab.clipboard.write([{ entries: [
     { mimeType: "text/plain", text: tsv },
     { mimeType: "text/html", text: html },
   ] }]);
   // 此前已通过界面确认目标网格选区；示例值不含制表符或换行。
   await tab.pressKey(null, "super+v");
   await tab.getAXState();
   ```

   示例只展示简单单元格；真实值含制表符或换行时，需要正确生成 TSV 引号与转义，不能直接照用示例的 `join`。

5. **每批立即回读。** 检查行数、列数、主键唯一性、目标字段和未改字段；不要在选区不明时继续粘贴，也不要把“调用未报错”当成写入成功。
6. **发生覆盖后，从基线恢复完整受影响范围。** 停止追加操作，将基线和已核实的变更合并成完整预期矩阵，排除本应保留只读的字段。本次在确认受影响表的完整可写列和网格选区后，一次粘贴完整矩阵，恢复了原有内容并补入新增行。该行为只在本次表结构下验证，不能假定任意表都能自动扩行或自动还原关联。
7. **刷新后再验收。** 重新从页面复制数据，按主键逐字段比较；关联字段检查真实关联结果，查找引用按父记录比较结果集合，顺序差异不视为缺失。检查原有记录的值、关联和用途均保留，新增行无遗漏或重复。视图筛选修改还需显式保存，再刷新确认筛选范围。

本次最终刷新后，受影响明细表与完整预期数据逐行一致；主表静态字段按主键比较无差异，关联及查找引用结果集合吻合，原有记录和新增记录均通过核对。
